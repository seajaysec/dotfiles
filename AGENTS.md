## Learned User Preferences

- Default to the simplest path that uses the tool's native capabilities. When the tool supports something natively (e.g., iTerm loading an external prefs folder, iTerm Session Restoration, built-in tmux integration), do not invent wrappers, symlinks, or shell shims around it.
- Never break existing terminal functionality. Verify in a fresh shell that PATH still resolves `mkdir`, `uname`, `date`, `stat`, `fzf`, `zoxide`, and `starship` after any change to `.zshrc`, `.zshenv`, `.zprofile`, or anything else that runs at shell init.
- Always test shell, tmux, iTerm, or editor changes in a clean window or process before reporting success. Do not claim work is done from inspecting the diff alone.
- When you are unsure how a tool works OR your current attempts are producing weird behavior, search for real working public examples (blog posts, GitHub repos, upstream READMEs, official docs) before improvising more attempts. Steal from proven working setups instead of drafting off your own interpretation. The user has called out "your hunches suck, find reliable resources" multiple times.
- When an approach keeps failing, stop and BRAINSTORM alternate models — do not laser-focus on troubleshooting the same broken approach. The user prefers "back to the drawing board" over more patches on a bad foundation, and explicitly says so when you keep drilling on a dead end.
- When the user asks a "why" question during troubleshooting (e.g., "why is this happening?" or "answer that question first, then fix it"), answer the question first before proposing a new fix. Do not propose the same solution multiple times — track what's been tried and rule it out before re-suggesting.
- Re-read the user's stated constraints before acting and do not undo decisions already made. If the user says something is wrong twice, change direction; do not paraphrase the same approach.
- For editor/IDE-like UIs (e.g., nvim file browser), target a macOS Finder "As Columns" feel: `l` drills into a directory or opens a file, `h` goes up a level, the current view is replaced rather than expanded inline as a tree.
- Match the user's Dracula Pro iTerm color scheme; avoid clashing default colorschemes in new tools.
- Treat the public remote as the source of truth that follows the user across machines. Push non-secret changes there and keep the installer able to bootstrap a new device from a clean clone.
- Prefer the modern CLI tools already installed: `eza` (not `ls`), `rg` (not `grep`), `fd` (not `find`), `bat`, `fzf`, `zoxide`, `starship`, `delta`, `tldr`.

## Learned Workspace Facts

- The canonical repo lives at `~/dotfiles`. `~/.zshrc`, `~/.zshenv`, `~/.zprofile`, and the VS Code / Cursor `settings.json` files are symlinks into this repo created by `./install.sh`. Edit the repo copies, never the home copies.
- Secrets stay out of the repo. Put them in `~/secrets.sh` (sourced from `.zshrc`) or `~/.zshrc.local`; never write tokens, credentials, internal hostnames, or work-only paths into tracked files.
- **iTerm persistence is native Session Restoration (NOT `tmux -CC`).** `config/iterm2/apply-iterm-defaults.sh` is the single, idempotent source of truth for prefs (status bar, snippets, triggers, keybindings, IRMemory, restoration). Required defaults: `killJobsInServersOnQuit=0`, `NSQuitAlwaysKeepsWindows=1`, `IRMemory=32`. If sessions still die on ⌘Q after running it, `cfprefsd` cached a stale value — toggle Settings → Advanced → Sessions → "User-initiated quit (⌘Q) of iTerm2 will kill all running jobs" OFF in the GUI once.
- `⌘T` = native iTerm tab, `⌘D` / `⇧⌘D` = native splits. `⌘Q` quits the iTerm UI but `iTermServer` daemons keep processes alive across relaunch (lost only on logout/reboot). Cross-reboot persistence still needs tmux — use the `tm` alias to attach/create session `$tmux_session` (default `main` from `.zshenv`); tmux is NOT auto-started.
- `config/iterm2/DynamicProfiles/` now holds **Automatic Profile Switching** profiles (per-project color/profile via Shell Integration), symlinked by `./install.sh --link-only`. iTerm hot-reloads dynamic profiles — no restart.
- Dotfiles-managed iTerm items use prefix `dotfiles-` (GUIDs) and `dotfiles:` (labels) so the apply script replaces only its own snippets/triggers/keybindings idempotently and preserves user-added ones.
- The iTerm status bar replaces Starship. Starship init is gated by `DOTFILES_PROMPT=starship` in `.zshrc`; default `iterm` skips it. The `python_venv` user_var is published by the `iterm2_print_user_vars` hook in `.zshrc`; per-machine PROMPT override goes in `~/.zshrc.local`.
- iTerm 3.6.9 crashes when opening the status bar setup UI if `iTermStatusBarVariableBaseComponent` is in the layout — use `iTermStatusBarSwiftyStringComponent` instead. Interpolated values in status bar strings use `\(user.python_venv)` syntax.
- Shell stack: `zap` plugin manager, `starship` prompt (optional, gated by `DOTFILES_PROMPT`), `zsh-autoswitch-virtualenv` for Python venvs at `~/.virtualenvs/{dirname}-{xxxx}`. When a project has no matching venv, fall back to the Homebrew/system Python instead of erroring at launch.
- `cd` is aliased to `zoxide` (`z`) for interactive use, but every function and alias in `.zsh.aliases` / `.zsh.functions` must invoke the real `cd` to stay safe under that aliasing.
- Key files for any shell/terminal behavior work: `.zshrc`, `.zshenv`, `.zsh.aliases`, `.zsh.functions`, `install.sh`, and the `config/iterm2/` tree (especially `apply-iterm-defaults.sh` and `README.md`). Read all of them before refactoring shell init.
- GSD (get-shit-done) workflow scaffolding lives at `~/.cursor/get-shit-done/` and `~/.cursor/skills/`. Slash commands like `/gsd-plan-phase`, `/gsd-execute-phase`, and `/gsd-verify-work` drive multi-phase work and write artifacts under `.planning/` in the current repo.
